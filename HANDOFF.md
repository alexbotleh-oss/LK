## 3. Текущая открытая задача
Проверить и исправить цепочку Android-сканера:

`camera input → barcode decode → result → existing Core/common handler`

Камера ранее открывалась, но decode не приводил к ожидаемому результату/обработчику. Два подхода к ZXing описаны в WORKLOG; не повторять их вслепую. Сначала исследовать актуальный код, диагностические события и текущую ветку кандидата.

## 4. Защищённые границы
- Не заменять WP непроверенным кандидатом.
- Не создавать второй Core или параллельный бизнес-путь.
- Камера — только источник ввода; результат направляется существующему обработчику.
- Не смешивать Products, Shopping и QR-контексты.
- Сканирование не должно выполнять неконтролируемую запись; для покупки/изменения требуется подтверждение.
- Не считать сборку или статический анализ доказательством работы камеры на реальном Android.
- Fix6/Flet и существующую бизнес-логику не переписывать без отдельного основания и разрешения.
- Перед патчем: WP/SHA verify → backup/snapshot → pre-check → минимальный патч → forward/reverse diff → UI и регрессии.

## 5. Обязательная регрессия
- RC-01: камера → decode → результат → handler.
- RC-02: Products / Shopping / QR не смешиваются.
- RC-03: Recipe/DB — список, добавление из БД, удаление, КБЖУ.
- RC-04: нормализация ингредиентов и сопоставление продуктов.
- RD-01: сверить источник истины Core/DB с артефактом.

Каждый доступный чат должен добавить свою подтверждённую часть в WORKLOG.md; полнота объединения отмечается только после сверки всех четырёх источников.
